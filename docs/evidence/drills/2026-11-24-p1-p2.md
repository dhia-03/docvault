# Incident response drills, 2026-11-24

Two technical run-throughs of the [incident response plan](../../incident-response-plan.md), on a fresh kind cluster with the code of branch `chore/hygiene` (all flaws fixed, O1 to O3, account controls, Falco). **They were run by Claude Code (AI), scripted, not by the team**: the times below are those of a script, not of people reading alerts. They prove that the detections fire and that the playbook commands work; a team rehearsal is still to be done.

Each step was written to a timeline with UTC timestamps, as the plan asks. The evidence (logs, pod manifest, audit export, file listings with SHA-256 sums) stayed outside the repository, as the plan's evidence rules require; only the timelines are kept here. No secret value appears in them.

## Findings

1. **A restart is not finished when `rollout status` says so.** In both drills the first request after `kubectl rollout restart` and `rollout status` was reset: the old pod was still terminating and still selected for a moment. In P2, `/healthz` even answered from the old pod. Before verifying, wait until a single app pod remains. Both playbooks now say so.
2. **The database password rotation works without the interactive `\password`.** P2 marked it untested. `ALTER ROLE ... PASSWORD` sent to `psql` on standard input, then the secret updated and the app restarted, worked, and the value never appears on a command line. The playbook now uses this form.
3. **Quarantine cuts DNS too.** The quarantined pod failed with `gaierror`: it could not resolve the database's name, so it could not reach it by name or by address.
4. **Signing one user out is enough for a stolen cookie.** Scenario A ended the thief's session without touching other users; the key rotation (scenario B) is only needed when the key itself may be known.
5. **Tools must be ready before the incident.** PyPI was unreachable from the machine during the drill; the scripts only ran from uv's offline cache. Keep the tools the playbooks use (`httpx`, `itsdangerous`, the pinned kubectl) installed in advance.
